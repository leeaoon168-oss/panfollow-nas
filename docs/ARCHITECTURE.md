# 架构

## 数据流

```
           ┌──────────── 抓取层（Playwright）────────────┐
documents  │  文档：滚动合并虚拟列表，抽出「剧名 + 分享链接」 │
(2 份)     │  表格：WPS 前端 API 逐格读文本与超链接          │
           └───────────────────┬────────────────────────┘
                               ▼
                        shows（剧）  ──▶  subs（订阅 + 起始集 + 检查周期）
                               │
                               ▼
                        sources（来源）
                   同一部剧可以挂 N 条分享链接
                   label 记录来自哪份文档；dead 标记失效
                               │
                      pick_source() 选优
                  ① 探测每个来源：转存 → 列目录 → 画质/集数
                  ② 缺集时「能覆盖需要的集数」优先于画质
                  ③ 画质接近（≤5%）或标签未知时问 AI
                  ④ 结果写 active
                               │
                               ▼
                     download_show()
          BaiduPCS-Go 转存 → walk 目录 → 与本地文件做差集
                    → 只下缺的集 → 校验落盘大小
                               │
                               ▼
                     /downloads/<剧名>/
```

## 关键模块

| 模块 | 职责 | 关键点 |
|---|---|---|
| `server.py` | 路由、编排、定时任务、SSE | 全局 `_PCS_LOCK` 串行化百度通道（BaiduPCS-Go 的工作目录是全局状态） |
| `store.py` | SQLite | `shows / subs / sources / documents / policy / files / notifications`；连接重试 5 次 |
| `kdocs.py` | 文档解析 | 虚拟列表必须滚动合并，否则只拿到首屏十几条 |
| `sheetlinks.py` | 表格解析 | 内容画在 canvas 上，DOM 里没有文字；走 `WPSOpenApi.KSheetApplication` 读 Range 与 `Hyperlinks.Item(1).Address` |
| `ai.py` | DeepSeek 仲裁 | 只回候选 id；结果按候选指纹缓存 6 小时；失败静默回退规则 |
| `notify.py` | 通知 | 多渠道路由 + 写历史；推送永不阻塞主流程 |

## 为什么"不做集数解析"

网盘分享里的文件名五花八门：

```
第06集.mp4    S01E06.mp4    06.4K.HDR.mkv    EP06 4K.mp4
```

任何正则都会在某个来源上翻车。改成**目录差集**：分享里有什么文件 vs 本地已有什么文件，
剩下的就是要下的 —— 与命名规则无关，天然幂等。

集数只用于"进度展示"和"完结判定"，不参与下载决策。

## 选源规则（`rank_sources`）

```
need = 文档集数（或总集数） - 本地已有集数

need > 0:
    ┌ 有来源能覆盖 need  → 在能覆盖的里面挑画质最好的
    └ 都覆盖不了        → 挑集数最全的（谁下得多先用谁）

need = 0（已下齐）:
    画质优先，集数差 ≤2 视为并列
```

## 失效处理

| 情况 | 处理 |
|---|---|
| 转存返回"分享已失效/取消分享/链接不存在" | 标 `sources.dead=1`，**立刻换下一条可用来源重试** |
| 来源还活着但集数不够 | 自动找更全的来源（`need` 优先） |
| 百度的"校验 BDUSS"接口被风控返回 HTML | 用 `pcs who` 复核，会话有效就继续 |
| 所有来源都不行 | 记 `dead:<slug>` 指纹，等清单更新出新链接再试 |

## 线程模型

- FastAPI（uvicorn）+ 一个下载 worker 线程 + 一个检查线程 + 一个刷新调度线程
- 百度相关操作全部串行（`_PCS_LOCK`），检查遇到下载会主动跳过
- 表格抓取和文档抓取共用无头 Chromium，抓完即释放
